# Контекст проекта vpn_script

> Обязательные правила разработки находятся в [AGENTS.md](AGENTS.md). Основная модель отвечает за результат целиком; делегирование Gemini через `agy` разрешено по правилам AGENTS.md. Другие субагенты и делегирование через внешние чаты запрещены. Этот документ содержит архитектурный контекст, а не дополнительные разрешения или задания.

## Назначение и поддержка

Проект автоматизирует установку и обслуживание 3X-UI, Xray-core, Nginx Stream SNI-preread, TLS-сертификатов, RU-Block и управляемых DNS-профилей.

Целевая приёмочная матрица — Ubuntu 22.04, Ubuntu 24.04 и Debian 12 на amd64. Полная ARM64-приёмка не подтверждена. Закреплённые версии и хеши компонентов определены в [lib/versions.conf](lib/versions.conf).

## Сетевая архитектура

1. Nginx Stream принимает публичный TCP/443 и анализирует SNI без расшифровки TLS.
2. SNI домена панели ведёт в локальную цепочку Steal-Oneself RAW → xHTTP → Unix-сокет Nginx; SNI Classic ведёт в Classic RAW → xHTTP → выбранный сторонний TLS-сайт на 443. Четыре REALITY-инбаунда имеют независимые ключи/short ID и слушают только loopback. PROXY protocol передаётся между локальными звеньями, перед внешним сайтом отключается. При недоступности Xray Nginx направляет HTTPS домена панели непосредственно на Unix-сокет.
3. Обычный HTTPS передаётся внутреннему виртуальному хосту Nginx через Unix-сокет с PROXY protocol. Nginx завершает TLS, проверяет SNI/Host и маршрутизирует запросы по путям и ожидаемым заголовкам.
4. VLESS xHTTP обслуживается Xray на loopback-порту за Nginx. Панель 3X-UI также слушает loopback и доступна через TLS-прокси по управляемому пути.
5. Обычные запросы обслуживаются заданным `-mask_upstream`. Чужой или отсутствующий SNI отклоняется.
6. Hysteria 2 принимает публичный UDP/443 с TLS; неавторизованные HTTP/3-запросы обслуживает тот же HTTP(S)-origin, что и сайт Nginx. Адрес и порт задаются через `-mask_upstream` и `-mask_port`.
7. Установщик экспортирует Xray-клиент xHTTP/TLS в закрытый JSON-файл. При заданном `-xhttp_download_path` точный HTTPS-маршрут Nginx отдаёт только этот экспорт после отдельной HTTP Basic-аутентификации. Путь файла, URL и origin сохраняются в состоянии развёртывания.
8. Правила Xray определяют разрешённые назначения, RU-Block и DNS-профиль. Доступ к приватным/локальным назначениям блокируется независимо от режима RU-Block.

Внутренние панель, API, подписки и xHTTP-backend не должны быть напрямую доступны извне по IPv4 или IPv6. Секретный путь и наличие TLS-прокси не заменяют изоляцию backend-listeners.

Всего управляются шесть инбаундов. Реестр `vpnScriptInbounds` в settings БД и поле `inbounds` закрытого state-файла связывают роли с ID/tag/port. Новые клиенты независимы; повторный запуск сохраняет ключи, пути и счётчики. Classic задаётся `-reality_target`, по умолчанию `www.microsoft.com`, с интерактивным запросом замены и обязательной проверкой сертификата/TLS 1.3/h2 перед применением. В dry-run сетевой этап Classic явно пропускается. Модуль `lib/reality.py` реализует эту проверку, реестр и добавление инбаундов.

DNS-профили: `none` (по умолчанию при чистой установке), `geohide`, `xboxdns`, `comss`. При обновлении без явного флага сохраняется предыдущий профиль. Домены, bootstrap-адреса и правила брать из текущей реализации; исторические IP провайдеров не являются нормативными значениями.

Текущая схема и пользовательские параметры описаны в [README.md](README.md).

## Проверки и восстановление

Все проверки исполняемого кода выполняются в Docker. На хосте допустимы просмотр/редактирование репозитория и проверенные Docker-обёртки. Тип задачи определяет необходимое покрытие по AGENTS.md; команды стендов находятся в разделе 7 README.

Перед изменением существующей БД установщик получает согласованный SQLite-снимок и проверяет целостность именно снимка. Операция хранит журнал и снимки в закрытом каталоге внутри `/var/lib/vpn-script/`. Восстановление ограничено ресурсами этой операции; при сбое восстановления журнал и снимки сохраняются.

Падение тестов не разрешает перезапуск служб хоста или production. Результаты прежних прогонов в walkthrough не заменяют проверку текущей ревизии.
